# Static OG image for `/plan/share` — Design

**Date:** 2026-05-26
**Phase:** Feature add (post-launch, follow-up to Share My Plan)
**Status:** Draft, awaiting user review

---

## Goal

When a Share My Plan URL (`/plan/share#…`) is pasted into iMessage, Slack, WhatsApp, Twitter, LinkedIn, or Discord, the recipient sees a branded rich preview card instead of a naked URL. This signals "this is a real product" and increases click-through on every share generated by the feature shipped earlier today.

Acceptance test:

> Sender clicks "Share my plan" in `/my-plan`, copies the link, pastes it into a Slack DM. Slack's unfurler fetches `https://nytw.dev/plan/share` (the path portion only — the hash never reaches the server). The response includes `og:image` pointing to `/plan/share/opengraph-image`, which returns a 1200×630 PNG with NYTW branding and the copy "Someone shared their NYTW plan with you." Slack renders the rich card.

---

## Decisions captured during brainstorm

| Topic | Decision |
| --- | --- |
| Personalization | **Static** — one image for every share URL. The plan content lives in the URL hash which never reaches the server, so personalized OG would require migrating to a query param and giving up the privacy guarantee made in the Share My Plan spec. The "rich preview vs naked URL" delta already captures most of the perceived value; sender-name + event-count personalization is deferred. |
| Visual style | Mirrors `app/opengraph-image.tsx` (the homepage OG): black background, `#FF5B25` festival eyebrow, white headline, `#9B9B9B` subhead, mono font stack. Different copy and layout proportions to clearly read as a *different page* in chat-app unfurls. |
| Copy | Headline: "Someone shared their NYTW plan with you." Subhead: "Open to see what they picked." Eyebrow: "TECH WEEK NYC · JUNE 1–7, 2026". Footer: "nytw.dev/plan". User explicitly approved. |
| Tech | Next 16 file-based OG convention — `app/plan/share/opengraph-image.tsx`. Next automatically wires this into `<meta property="og:image">` and `<meta name="twitter:image">` for any URL under `/plan/share`. No `metadata` edits needed in `page.tsx`. |
| Runtime | Node.js (not Edge). Mirrors the homepage OG, which has a comment explaining the Vercel Hobby 1MB Edge limit was the deciding factor. OG images are cached by social platforms anyway, so cold-start latency is irrelevant. |
| Caching | Default Next 16 OG caching (image is statically computed at request time, then cached by the social platform's unfurler — Twitter, Slack, etc. cache aggressively). No additional `revalidate` config needed. |
| Twitter Card | Next 16 emits both `og:image` and `twitter:image` from the same file. No separate Twitter meta file. |
| Testing | One smoke test imports the route, exercises the default export, asserts content-type is `image/png` and the exported constants (`alt`, `size`, `contentType`) match the spec. No visual regression — too brittle and the homepage OG sets the visual contract. |

## Architecture

```
app/plan/share/
  page.tsx                  (unchanged — Share My Plan recipient route)
  SharedPlanClient.tsx      (unchanged)
  opengraph-image.tsx       NEW — exports default async Image() returning ImageResponse,
                                  plus alt / size / contentType constants
```

Next 16 picks up `opengraph-image.tsx` co-located with `page.tsx` and:
1. Generates the image at request time via `ImageResponse`.
2. Adds `<meta property="og:image" content="/plan/share/opengraph-image">` to the page's `<head>`.
3. Adds the corresponding `twitter:image` tag.
4. Sets `og:image:width=1200`, `og:image:height=630`, `og:image:alt=<alt>` automatically from exported constants.

No data flow beyond rendering JSX into an `ImageResponse`. The image is identical for every share URL, so the hash payload is irrelevant to image generation.

## Component

`app/plan/share/opengraph-image.tsx`:

- `export const alt` — short description for screen readers and link unfurlers that surface it.
- `export const size = { width: 1200, height: 630 }`.
- `export const contentType = 'image/png'`.
- `export default async function Image(): Promise<ImageResponse>` — composes the JSX above into `new ImageResponse(<div>…</div>, { ...size })`.

No external font loading. Falls back to the same `ui-monospace, SFMono-Regular, Menlo, monospace` stack the homepage OG uses — keeps the bundle small and avoids the cold-start cost of fetching a font file.

---

## Testing

`__tests__/app/share-og.test.ts`:

- Imports the route module.
- Asserts `alt` is a non-empty string mentioning "NYTW" or "plan".
- Asserts `size.width === 1200` and `size.height === 630`.
- Asserts `contentType === 'image/png'`.
- Calls `Image()` and asserts the returned `Response` has `content-type: image/png`.

No visual regression. The homepage OG (`app/opengraph-image.tsx`) sets the visual contract; if it ever breaks visually, the share OG will reveal the same regression — one test there is enough.

## Edge cases

| Case | Behaviour |
| --- | --- |
| Bundle size > 1MB on Edge runtime | Use Node.js runtime (default). Mirrors homepage OG's documented decision. |
| Social platform doesn't fetch the OG | No degradation — they fall back to showing the raw URL, which is the current state. Pure improvement. |
| Hash payload tampering / arbitrary URL parameters | OG image is identical regardless. Cannot be exploited for content injection. |
| iMessage requests OG | Apple's link preview service fetches the URL server-side and reads `<meta>` tags. Works exactly like Slack/Twitter. |
| Sender shares URL on Twitter where Twitter Card crawler hits the path | Twitter reads both `og:` and `twitter:` tags. Next 16 emits both. ✅ |
| OG cached stale by social platform | Each platform manages its own cache (Twitter ~7 days, Slack ~1h, Facebook indefinite until refresh tool). Acceptable — content is static. |

## Out of scope (deferred — explicit)

- **Per-share personalization** (sender name, event count, first event titles). Would require URL migration from hash → query param and giving up the privacy guarantee from the Share My Plan spec. Re-open as a separate spec once we have signal that socials are converting.
- **Dynamic OG per individual event** (`/events/[id]/opengraph-image`). Separate feature, separate spec, only worth doing once we have per-event share URLs (which we don't yet).
- **A/B test of OG copy variants.** No traffic yet to validate variants against. Single canonical copy ships first.
- **Twitter-specific Card variants** (e.g., `summary_large_image` vs `app` cards). The default `summary_large_image` shape Next emits for 1200×630 is fine.
- **Localized OG** (Polish-language variant). Audience for shares is mixed; English is the safe default given NYTW is in NYC.

## Migration / compatibility

- Net-new file. No existing OG metadata on `/plan/share` page (verified by reading `app/plan/share/page.tsx`).
- Pre-existing `metadata.title` and `metadata.description` on `/plan/share` are kept — Next 16 OG file convention is additive.
- No changes to `app/opengraph-image.tsx` (homepage OG). The two coexist; Next selects the closest co-located OG image at request time.
- No URL changes. No user-facing breakage possible.
